# UI

Слой графических примитивов и текстовых полей поверх `Display` (`App/Display`). Не знает про SPI/DMA/ST7789 — работает только через контракт `display.h`.

Состоит из двух частей:

- **`gfx.c` / `gfx.h`** — низкоуровневая отрисовка текста, посимвольно, неблокирующая.
- **`text_field.c` / `text_field.h`** — строительный блок "текстовое поле" с dirty-трекингом поверх `gfx`, для любых значений, меняющихся во время работы (температура, статусы и т.д.).

Оба модуля построены на одном принципе: **ничего не блокирует главный цикл**. Ни одна функция не ждёт DMA — важно, потому что главный цикл параллельно крутит PID/safety-логику, и скорость SPI-дисплея не должна на неё влиять.

## gfx — отрисовка текста

Неблокирующая модель "поставь задание — продвигай по кусочку":

- `Gfx_DrawTextStart(x, y, text, prev_x, prev_text, font, fg_color, bg_color)` — ставит текст в очередь на отрисовку. Не блокирует, не рисует сразу.
- `Gfx_Process()` — вызывается из главного цикла каждую итерацию, продвигает текущее задание на один символ за вызов, если DMA свободен; если DMA занят — сразу возвращает управление.
- `Gfx_MeasureTextWidth(font, text)` — считает ширину строки в пикселях, не рисуя (пропускает символы, отсутствующие в шрифте — так же, как это делает сам рендер).
- `Gfx_CancelJob()` — принудительно отменяет текущее задание, не дожидаясь его естественного завершения по символам. Нужна там, где владелец задания решает, что начатая отрисовка больше не актуальна и больше не будет звать `Gfx_Process()` для неё (иначе `s_job` молча остаётся в `GFX_JOB_BUSY` навсегда, и следующий `Gfx_DrawTextStart()` — для ЛЮБОЙ строки, задание общее на весь модуль — будет отклоняться по кругу). Блокирующая: ждёт `Display_IsBusy() == false`, прежде чем сбросить состояние — короткая (последний начатый DMA-чанк), не для вызова на каждой итерации главного цикла. Единственный вызывающий сейчас — `TextField_InvalidateAll()`, см. ниже.

Статусы задания — `Gfx_JobState_t`: `GFX_JOB_IDLE`, `GFX_JOB_BUSY` (есть символы для отрисовки), `GFX_JOB_DONE` (завершено на предыдущем вызове `Gfx_Process()`), и два состояния ошибки — `GFX_JOB_ERROR_FATAL` и `GFX_JOB_ERROR_RETRY`. Разделены намеренно, чтобы вызывающей стороне (`text_field.c`) не нужно было знать, что именно пошло не так внутри `gfx.c` — только что делать дальше.

- **`GFX_JOB_ERROR_FATAL`** — некорректные аргументы при `Gfx_DrawTextStart()` (`text`/`font` == NULL). Баг конфигурации вызывающего кода, не транзиентная штука — повторная попытка теми же аргументами даст тот же результат.
- **`GFX_JOB_ERROR_RETRY`** — отказ `Display_SetWindow()` или `Display_WritePixelsDMA()` (любой из двух вернул не `DISPLAY_OK`) в середине уже идущего задания, включая настройку окна стирания старого прямоугольника в `Gfx_DrawTextStart()`. В этом случае `Gfx_Process()` сразу останавливает обработку задания, не отправляя дальнейшие символы/чанки поверх неисправной шины. Раньше (до исправления) отказ `Display_SetWindow()` везде проглатывался молча (символ/стирание просто пропускались, курсор всё равно двигался дальше, будто всё в порядке) — теперь любой такой отказ переводит задание в `GFX_JOB_ERROR_RETRY`.

`DISPLAY_OK` от `Display_WritePixelsDMA()` означает только то, что DMA-передача СТАРТОВАЛА — не то, что она гарантированно завершится; асинхронное завершение (успех/сбой) обрабатывает сам драйвер дисплея (`HAL_SPI_TxCpltCallback()` в `st7789.c`), `gfx.c` этим не занимается.

Вызывающая сторона (`text_field.c`) трактует оба состояния ошибки **не** наравне с `GFX_JOB_DONE`, но по-разному между собой:
- `GFX_JOB_ERROR_RETRY`: экран после отказа посреди задания находится в неизвестном состоянии (возможно, часть нового текста уже легла поверх части старого прямоугольника стирания, либо старый прямоугольник вообще не был стёрт), поэтому `shown_text`/`shown_x` строки не обновляются (остаются последним достоверно отрисованным состоянием), а сама строка повторно помечается `dirty` — на следующей итерации главного цикла она перерисовывается заново тем же (или уже новым, если пришли новые данные) текстом.
- `GFX_JOB_ERROR_FATAL`: `dirty` НЕ взводится — иначе строка с бракованной конфигурацией вечно выбиралась бы первой и блокировала отрисовку остальных dirty-строк (`TextField_Process()` обрабатывает не более одной строки за вызов).

В обоих случаях не зацикливается — `s_active_line` сбрасывается, следующая грязная строка будет обработана на следующем `TextField_Process()`.

**Модель "стереть старое, нарисовать новое"**: если `prev_text` не пуст, перед отрисовкой новой строки сначала стирается прямоугольник, где была нарисована `prev_text` (по `prev_x` и ширине стирания). Это одним механизмом покрывает все случаи — новая строка короче/длиннее старой и/или сдвинута по x (например, при перецентровке) — без частных случаев и "призраков" старого текста на экране.

Ширина стирания считается **не** через `Gfx_MeasureTextWidth()` (сумма типографских advance), а через внутренний `measure_real_right_edge()` — реальный правый край нарисованных пикселей. У части глифов "чернила" на 1px шире собственного advance (например "4" в `AntiquaB_18_uni`), и стирание по advance оставляло столбец-призрак, который никогда не стирался. `Gfx_MeasureTextWidth()` по-прежнему используется там, где нужен именно типографский шаг курсора — позиционирование/центровка (`TextField_PrintfCentered`/`PrintfRightAligned`, расчёт `s_sleep_icon_x` в `Screen`), а не размер прямоугольника стирания.

## text_field — текстовые поля с dirty-трекингом

Задача: развязать "когда изменилось значение" и "когда физически прорисован дисплей".

Модель:
- Каждая строка (индекс `0..TEXTFIELD_MAX_LINES-1`, по умолчанию 24) имеет фиксированные позицию/шрифт/цвета, задаваемые один раз через `TextField_ConfigureLine()`.
- `TextField_Printf()` обновляет содержимое строки немедленно во внутренних данных и помечает её "грязной" только если текст реально изменился — не рисует и не ждёт DMA, можно звать даже из высокочастотного цикла опроса АЦП.
- `TextField_Process()` вызывается из главного цикла каждую итерацию: продвигает текущее задание `gfx` (если есть), и когда `gfx` свободен — забирает одну грязную строку и запускает её отрисовку. За один вызов запускает не более одной новой грязной строки. При `GFX_JOB_ERROR_RETRY` строка НЕ помечается показанной и `dirty` взводится повторно (перерисуется на следующей итерации); при `GFX_JOB_ERROR_FATAL` — наоборот, `dirty` не взводится, чтобы бракованная строка не блокировала остальные (см. подробности в разделе `gfx` выше).
- Если рендер отстаёт от реальности — строки просто "состарятся" на кадр-два; момент изменения значения фиксируется точно, без пропусков и без пачки ("burst") тиков после долгого рендера.

### API

| Функция | Назначение |
|---|---|
| `TextField_Init()` | Сбросить все строки в неиспользуемое состояние (вызвать один раз при старте) |
| `TextField_ConfigureLine(line, x, y, font, fg, bg)` | Задать геометрию/стиль строки (один раз на строку) |
| `TextField_Printf(line, fmt, ...)` | Обновить текст строки (без перерисовки, если текст не изменился) |
| `TextField_PrintfCentered(line, center_x, fmt, ...)` | Как выше, но с центровкой по реально измеренной ширине текста (важно для значений с переменным числом цифр, например температуры — иначе текст "плывёт" от центра) |
| `TextField_PrintfRightAligned(line, right_edge_x, fmt, ...)` | Как `Printf`, но выравнивание по правому краю |
| `TextField_SetColors(line, fg, bg)` | Сменить цвета строки на лету (например, притушить неактивный канал); не трогает текст, всегда принудительно помечает строку грязной — в отличие от `ConfigureLine`, который для начальной настройки |
| `TextField_InvalidateAll()` | Забыть, что реально отображено на всех строках, и принудительно пометить их все грязными — без фазы стирания (предполагается, что экран уже физически стёрт снаружи, например заливкой через `Display_FillColorDMA`). Очищает у каждой строки не только `shown_text` (что физически на экране), но и сам желаемый `text` — строки, которые никто не собирается перепечатывать сразу после (например, статичный текст, напечатанный один раз при `Screen_Init()` — заголовки каналов, см. `Screen.md`), после этого вызова остаются пустыми до следующего явного `TextField_Printf()`. Если было незавершённое задание `gfx` (`s_active_line >= 0`) — вызывает `Gfx_CancelJob()`, иначе оно молча зависло бы в `GFX_JOB_BUSY` и блокировало отрисовку вообще всех строк. Нужно при переключении между полностью разными экранами (главный ⟷ сервисное меню) |
| `TextField_Process()` | Продвинуть рендер (вызывать из главного цикла каждую итерацию) |
| `TextField_GetShownWidth(line)` | Ширина (px) реально нарисованного сейчас на экране текста строки. Пока строка не `settled` (см. ниже), отражает СТАРЫЙ текст — актуальна только после `TextField_IsSettled()` |
| `TextField_IsSettled(line)` | true — внутренний текст строки совпал с реально нарисованным (`shown_text`), т.е. рендер этой строки полностью догнал последнее изменение. Нужно там, где позиционирование зависит от уже физически показанной ширины (см. `s_sleep_icon_x` в `Screen.md`) |

Константы: `TEXTFIELD_MAX_LINES` (по умолчанию 24), `TEXTFIELD_LINE_TEXT_MAX` (по умолчанию 96, текст обрезается по этому лимиту).

## Связь с гейтингом главного цикла

`TextField_Process()` вызывается из главного цикла **без** тайминг-гейта (в отличие от `Screen_Update()`, гейтящегося по `SCREEN_UPDATE_MS`) — см. `Screen.md` / `README.md`.
