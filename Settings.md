# Settings

Конфигурация станции: пресеты, текущая уставка, sleep-параметры, калибровка (slope/bias), тайминги sleep, коэффициенты PID и глобальные флаги. Персистится в EEPROM целиком, с отложенной записью через `Settings_Poll()`.

Чистое хранилище данных — намеренно **не знает** ни про `state.h` (`fixed_t`/PID), ни про `buttons.h`. Разделение ответственности:

- Ввод (кнопки) пишет `setpoint_temp` — этот же слой (Input/UI, т.е. `Fsm`), выбирая пресет или меняя target, обязан **сам** продублировать значение в `State` через `State_SetSetpointTemp(ch, FIXED_FROM_INT(value))`. `Settings` не дёргает `State` самостоятельно — иначе у `setpoint_temp` появятся два независимых писателя (см. `FSM.md`).
- `Kp/Ki/Kd` хранятся как `uint16_t` (сырое значение) — синхронизировать не с чем, зеркального поля в `state.h` нет. `Control` читает их напрямую (`Settings_GetKp/Ki/Kd`) и сам конвертирует в `fixed_t` при необходимости.
- `uint16_t` вместо `fixed_t` — удобно для UI (целые градусы/величины) и для записи в EEPROM (2 байта на значение).

**Клампинг**: все сеттеры молча зажимают входное значение к допустимому диапазону — не отбрасывают.

**Отложенная запись**: любой сеттер, реально изменивший значение (после клампинга), взводит внутренний таймер на `SETTINGS_SAVE_DELAY_MS` (1500 мс). `Settings_Poll()` (вызывать из главного цикла) фактически пишет в EEPROM, когда с последнего изменения прошло это время без новых изменений ("отпустили кнопку и подождали"). `Settings_Save()` — публичная функция для немедленного принудительного сохранения (используется `Fsm` при полном выходе из меню).

## Диапазоны значений

| Величина | Диапазон | Примечание |
|---|---|---|
| Температурные уставки (preset*, target, presleepTemp) | 50–450 °C | `SETTINGS_TEMP_MIN/MAX` |
| Тайминги Sleep | 0–30 мин | `SETTINGS_SLEEP_TIMEOUT_MIN/MAX_MINUTES` |
| Slope | 1–10000 (реальное 0.001–10.0, масштаб ×1000) | ⚠️ временный диапазон, не уточнён окончательно; нижняя граница строго > 0 — используется как делитель в `t=(R-bias)/slope` |
| Bias | 0–1000 (реальное 0–100.0, масштаб ×10) | ⚠️ временный диапазон |
| Kp/Ki/Kd | 0–10000 | ⚠️ временный диапазон — масштаб/единицы ещё не определены |

## Значения по умолчанию (`Settings_Init()`)

- Пресеты: preSet1=300, preSet2=350, preSet3=450 °C (оба канала)
- target = 300 (= preSet1)
- presleepTemp = 150 °C
- preSleepTimeout = sleepTimeout = 0 мин (sleep выключен, пока логика не реализована)
- Kp = Ki = Kd = 0 (регулятор неактивен, пока не настроен)
- slope/bias — номиналы из формулы датчика (72 / 217)
- flags = 0

Значения без явного задания от пользователя помечены в реализации как временные, подлежат уточнению.

## Загрузка из EEPROM (`Settings_Load()`)

Три различных исхода — не просто `bool` (`SettingsLoadStatus_t`), т.к. `IO_ERROR` и `INVALID` требуют разной реакции наверху (в будущем — модуля `Error`):

| Статус | Когда | Поведение |
|---|---|---|
| `SETTINGS_LOAD_OK` | Всё сошлось, все поля валидны | Загружены сохранённые значения |
| `SETTINGS_LOAD_IO_ERROR` | Ошибка связи по I2C, микросхема не отвечает | В RAM — значения по умолчанию; в EEPROM ничего не пишется (бессмысленно при нерабочей шине) |
| `SETTINGS_LOAD_INVALID` | (а) magic/checksum не сошлись (новый/заменённый чип либо повреждение), или (б) checksum сошёлся, но поле вне диапазона (редкое совпадение) | (а) — чип стирается целиком (0xFF) и пишутся дефолты. (б) — конкретное поле молча зажимается к границе, исправленное значение ставится на отложенную запись |

Статус `INVALID` **не** называется "CORRUPTED": на чистом/новом чипе magic просто не совпадёт с ожидаемым — это отсутствие данных, а не их повреждение. Важно: даже если запись дефолтов после `INVALID` прошла успешно, сам факт невалидности **не гасится** — ожидается, что вызывающий код (будущий `Error`) покажет предупреждение об этом до конца текущего сеанса.

## API (`settings.h`)

### По каналам (`channel_id_t ch`)

| Get/Set | Величина |
|---|---|
| `Settings_[Get\|Set]Preset(ch, preset)` | Значение пресета (`PRESET_1/2/3`) |
| `Settings_[Get\|Set]Target(ch)` | Текущая активная уставка (только хранение — синхронизация с `State` на совести вызывающего) |
| `Settings_[Get\|Set]PresleepTemp(ch)` | Температура Sleep |
| `Settings_[Get\|Set]Slope(ch)` / `Bias(ch)` | Калибровка линеаризации RTD |
| `Settings_[Get\|Set]PreSleepTimeout(ch)` / `SleepTimeout(ch)` | Тайминги sleep, минуты |
| `Settings_[Get\|Set]Kp/Ki/Kd(ch)` | Коэффициенты PID |

### Глобальные флаги

- `SETTINGS_FLAG_BUZZER_BIT` — бит зуммера (пункт "Bzzz" в сервисном меню).
- `Settings_[Get\|Set]Flags()` — весь байт целиком.
- `Settings_[Get\|Set]FlagBit(bit_index, value)` — один бит (0..7).

### Персист

| Функция | Назначение |
|---|---|
| `Settings_Save()` | Немедленно сохранить весь конфиг в EEPROM. Обычно вызывать напрямую не нужно — см. `Settings_Poll()`. Полезна для гарантированного немедленного сохранения (например, по сигналу о пропадании питания) |
| `Settings_Poll()` | Вызывать периодически из главного цикла — выполняет `Settings_Save()`, если было изменение и прошло не менее `SETTINGS_SAVE_DELAY_MS` без новых изменений. Не блокирует |
| `Settings_Load()` | Загрузить конфиг из EEPROM в RAM, вызывать один раз при старте. Возвращает `SettingsLoadStatus_t` |
| `Settings_ResetToDefaults()` | Стереть EEPROM целиком и записать дефолты — тот же путь восстановления, что и при `Settings_Load()` с невалидными данными. Публичная обёртка для пункта "Сброс" в сервисном меню (Expert) |
| `Settings_Init()` | Установить значения по умолчанию всем каналам (не трогает EEPROM) |
