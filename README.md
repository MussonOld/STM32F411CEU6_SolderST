# STM32F411CEU6_SolderST

Прошивка паяльной станции на базе **STM32F411CEU6** (STM32CubeIDE).

## Статус проекта

> 🚧 В разработке.

## Аппаратная часть

- МК: **STM32F411CEU6** (Cortex-M4, чип до 100 МГц; в `SystemClock_Config()` сконфигурировано **96 МГц** — HSE 25 МГц, PLLM=25/PLLN=192/PLLP=2, AHB `/1`)
- Дисплей: **TFT на контроллере ST7789**, интерфейс **SPI1**
- EEPROM: **24C04**, интерфейс **I2C1** — хранение настроек
- Таймеры: **TIM2, TIM3, TIM5, TIM10** — тайминги опроса/дебаунса, системные задачи
- **SPI2** — под 2× **ADS1220** (АЦП для термопар/RTD), пока не распаяны — плата (PCB) ещё не готова
- Кнопки — опрос через GPIO с программным дебаунсом (`App/Buttons`)

├── Settings/        — пользовательские настройки, загрузка/сохранение

## Важные особенности реализации

- **Тайминг-гейт опроса** (`SCREEN_UPDATE_MS`, `BUTTONS_POLL_MS`): `Screen_Update()` и опрос кнопок вызываются не на каждой итерации главного цикла, а с гейтом по времени (~30 мс и ~10 мс соответственно), без дрейфа (`+= period`, а не `= HAL_GetTick()`). `TextField_Process()` вызывается без гейта.
- **Сервисное меню**: два уровня доступа (User/Expert), навигация и редактирование параметров.
- **Обработка ошибок**: модуль `Error` интерпретирует статус EEPROM и диагностику RTD/нагревателя, блокирует фокус/управление на неисправном канале.
- **Settings**: `Settings_Load()` возвращает статус (`IO_ERROR` / `INVALID` / `OK`) вместо простого `bool`; статус `INVALID` не гасится успешным восстановлением значений по умолчанию.
- **Sleep-таймеры** выводятся в инфозону экрана (слева/справа — таймеры, по центру — статус EEPROM).
- **Запись изменений в EEPROM — по-разному в двух режимах**: в главном рабочем экране запись **отложенная** (`Settings_Poll()`, спустя `SETTINGS_SAVE_DELAY_MS` тишины после последнего изменения); при **выходе из сервисного меню** в главный экран запись **немедленная** (`fsm.c` форсирует `Settings_Save()`, не дожидаясь таймера) — см. `Settings.md`/`Menu.md`.
- **⚠️ Регенерация из `.ioc`**: STM32CubeMX перезаписывает такие файлы, как `main.c`, при каждой генерации кода, сохраняя только содержимое внутри `/* USER CODE BEGIN ... */ ... /* USER CODE END ... */`. Любой ручной код (переменные, вызовы функций) вне этих секций **будет потерян** при следующей регенерации — весь пользовательский код должен находиться строго внутри USER CODE-секций.
