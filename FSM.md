# FSM

FSM главного экрана: активный канал, разбор событий `Buttons` в изменения `Settings`/`State`, ускоренное изменение уставки при удержании UP/DN, вход/выход в сервисное меню (`Menu`).

Единственный писатель в `State_SetSetpointTemp()`/`State_SetEnabled()` со стороны пользовательского ввода (правило зафиксировано в `settings.h`: `Settings` сам не трогает `State`, это делает `Fsm`). При старте этим модулем синхронизируется в `State` только `setpoint_temp` — `InputFSM_SyncStateFromSettings()`. Поле `enabled` в `Settings`/EEPROM не хранится вообще — его дефолт задаётся прямо в `State_Init()` (см. `State.md`), а не синхронизацией отсюда.

`InputFSM_Poll()` вызывается из главного цикла каждую итерацию, **после** `Buttons_Poll()`. Не блокирует.

## Правила ввода

- **TOOLS** (короткое, единственное разрешённое для неё) — переключает активный канал. Работает **всегда**, в любом режиме экрана, в т.ч. внутри сервисного меню (меню наследует активный канал). При старте активен `CHANNEL_SOLDER`. Фокус не передаётся на неисправный канал (`Error_IsChannelBlocked`) — кроме случая, когда неисправны оба канала одновременно (тогда переключение разрешено, чтобы не застрять на одном канале без возможности увидеть второй; управление всё равно заблокировано на обоих).
- Все остальные кнопки управляют **только активным каналом**.
- **SET1/2/3 короткое** — `target` = соответствующий пресет.
- **SET1/2/3 длинное** — соответствующий пресет = текущая температура (с защитой от аномального/отрицательного чтения датчика; клампится 50..450 внутри `Settings`).
- **UP/DN короткое** — `target += / -= 1`.
- **UP/DN длинное** — авто-повтор с ускорением: шаг 1 десять итераций, затем округление вверх до 5 и шаг 5 пять итераций, затем округление вверх до 10 и шаг 10 до отпускания. Основано на `Buttons_IsHeld()` (уровень), не на повторных событиях — `Buttons` отдаёт только одно `LONG_PRESS` на факт удержания.
- **UP+DN короткий аккорд** — переключить активный канал (`State_SetEnabled(ch, !State_IsEnabled(ch))`). При включении (не при выключении) дополнительно сбрасывает таймер сна канала в `AWAKE` — `Sleep_ForceAwake(ch)`, см. `Sleep.md` — иначе только что включённый инструмент мог тут же оказаться в PRESLEEP/SLEEP, если простаивал ещё до включения.
- **UP+DN длинный аккорд** — переход в сервисное меню (`SCREEN_MODE_SERVICE` + `Menu_Init()`, всегда с чистого состояния: уровень User, курсор на первом пункте).
- Нарушения ввода (`BUTTON_EVENT_VIOLATION`) игнорируются молча.
- Если активный канал неисправен (`Error_IsChannelBlocked`) — управление (SET/UP/DN) заблокировано; TOOLS и UP+DN аккорд под этот блок не подпадают (обрабатываются раньше).

## Сервисное меню — вход/выход

Пока `s_screen_mode == SCREEN_MODE_SERVICE`, `dispatch_event()` перехватывает глобальные жесты выхода **до** передачи события в `Menu` (`Menu` их никогда не видит):

- Длинный аккорд UP+DN, либо короткое SET1, либо короткое SET3 — глобальный выход из **любого** уровня меню сразу в главный экран.
- Иначе событие передаётся в `Menu_HandleEvent(ev)`; если результат — `MENU_ACTION_EXIT_TO_MAIN` (пункт "Выход" уровня User) — тот же выход.

В обоих случаях запись в EEPROM форсируется немедленно через `Settings_Save()`, не дожидаясь обычного отложенного таймера `Settings_Poll()`, и режим экрана переключается обратно в `SCREEN_MODE_MAIN`.

## API (`fsm.h`)

| Функция | Назначение |
|---|---|
| `InputFSM_Init()` | Активный канал = `CHANNEL_SOLDER`, режим = `SCREEN_MODE_MAIN` |
| `InputFSM_SyncStateFromSettings()` | Отразить в `State` то, что реально загружено в `Settings`, для каждого канала. Вызвать ровно один раз при старте, сразу после `Settings_Load()`, до входа в главный цикл — иначе `State_GetSetpointTemp()` останется 0 (дефолт `State_Init()`) до первого нажатия кнопки, хотя `Settings` и экран уже показывают загруженное значение (рассинхрон, заметный будущему Control/PID) |
| `InputFSM_Poll()` | Один шаг: разобрать очередь событий `Buttons` + продвинуть авто-повтор UP/DN. Вызывать из главного цикла каждую итерацию, после `Buttons_Poll()` |
| `InputFSM_GetActiveChannel()` | Текущий активный канал (для `Screen` — какую половину рисовать ярко) |
| `InputFSM_GetScreenMode()` | Текущий режим экрана — `SCREEN_MODE_MAIN` / `SCREEN_MODE_SERVICE` (для `Screen` — что рисовать) |

## Связь с другими модулями

- Пользовательские события кнопок — из `Buttons` (`App/Buttons`).
- Сервисное меню — `Menu` (`App/Menu`), см. `Menu.md`.
- Пишет в `State`/`Settings` (`App/State`, `App/Settings`).
- Пишет в `Sleep` (`App/Sleep`) — `Sleep_ForceAwake(ch)` при включении канала аккордом, см. `Sleep.md`.
- Проверка неисправности канала — `Error_IsChannelBlocked()` (`App/Error`).
- Читается `Screen` для выбора активного канала/режима отрисовки — см. `Screen.md`.
