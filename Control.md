# Control

Управление нагревом каналов: ПИД-регулятор с непрерывным выходом 0–100 % и программным ШИМ. Модуль `App/Control` (`control.h` / `control.c`). Единственный писатель `State.current_temp` / `State.heater_active` и физических выходов `Solder_On` / `Desolder_On`.

## Выход

- `Solder_On` / `Desolder_On` — **активный низкий** (низкий уровень = нагреватель включён).
- Мощность задаётся долей времени включения в окне `CONTROL_PWM_PERIOD_MS` (200 мс): при опросе 10 мс это 20 шагов по 5 %. Тепловая постоянная жала — секунды, окно 200 мс незаметно.
- Окно второго канала сдвинуто на полпериода: гарантированно без пересечения, только пока оба duty ≤ 50 %. Выше 50 % (на любом из каналов) окна начинают перекрываться — оба нагревателя могут какое-то время греть одновременно; жёсткий сдвиг на полпериода не подстраивается под фактические duty и не всегда даёт минимально возможное перекрытие.
- Вид выходной ступени изолирован в `pwm_stage()` — при переходе на аппаратный ШИМ (TIM3_CH1/CH2, PB4/PB5) меняется только она.

## Регулятор

```
output = Kp·e + Ki·I − Kd·dT/dt,   клампится в [0, 100] %,   e = уставка − температура
```

- Коэффициенты хранятся в `Settings` как целые: `real = raw / CONTROL_PID_SCALE` (100). Единицы: Kp — %/°C, Ki — %/(°C·с), Kd — %/(°C/с). Правятся в Expert-меню.
- **Kd действует на измерение**, а не на ошибку — при смене уставки нет всплеска. `dT/dt` сглаживается экспоненциальным фильтром (`CONTROL_DTDT_FILTER_MS`).
- **Анти-виндап Ki**: интеграл копится только при `|e| <= CONTROL_INTEGRAL_BAND_C`, вне полосы сбрасывается в 0; вклад `Ki·I` клампится в [0, 100] %. При перелёте (`e < 0`) потолок интеграла падает пропорционально величине перелёта (`CONTROL_OVERSHOOT_GAIN`).
- **Kp = Ki = Kd = 0** → `output = 0`, нагрев не включается.
- Шаг PID и производная пересчитываются только на реально новый отсчёт АЦП (~раз в 50 мс при 20 SPS); фаза ШИМ обновляется на каждый вызов.

### Двухстадийная уставка

При скачке уставки ПИД, идущий сразу на новую цель, надолго насыщает выход, и торможение по Kd срабатывает поздно — перелёт. Поэтому, пока температура ниже `уставка − CONTROL_APPROACH_OFFSET_C`, ПИД гонит на промежуточный рубеж; достигнув его, переключается на настоящую уставку. Оставшийся шаг меньше пропорциональной полосы (`100/Kp`), и доход идёт гладко. Фактический отступ `min(CONTROL_APPROACH_OFFSET_C, (уставка − температура)/2)`. `CONTROL_APPROACH_OFFSET_C` = 15 фиксирован и рассчитан на Kp ≲ 6.7 (`raw` ≲ 667): при большем Kp полоса `100/Kp` уже 15 °C, и выигрыш от двух стадий пропадает (регулятор остаётся рабочим за счёт Kd и анти-виндапа).

Правило — чистая функция `(температура, уставка)`, без состояния и рампы: малый скачок уставки (меньше отступа) не тормозится, при просадке под нагрузкой первая стадия включается снова сама.

## Когда нагрев принудительно выключен

`force_off()` — выход 0, нагреватель выключен, состояние PID сброшено. Условия:

| Условие | Источник |
|---|---|
| Нет ни одного валидного отсчёта АЦП (греть вслепую нельзя) или `Diag` ещё не оценил последний отсчёт (нарушен порядок `ADS1220 → Diag → Control`) | `ADS1220_IsDataValid()`, `Diag_IsSampleEvaluated()` |
| Канал заблокирован: любая неисправность канала, включая «инструмент не подключен», а также авария БП | `Error_IsChannelBlocked()` |
| Канал выключен аккордом UP+DN | `State_IsEnabled()` |
| Режим `SLEEP_MODE_SLEEP` | `Sleep_GetMode()` |

## Sleep

- `SLEEP` — нагрев выключен.
- `PRESLEEP` — работает как обычно, но эффективная уставка = `min(уставка, PresleepTemp)` (`Control_PresleepSetpoint()`): режим ожидания никогда не греет выше заданной уставки. `State.setpoint_temp` при этом не меняется. Тем же правилом пользуется `Screen`, чтобы поле уставки показывало применяемое значение.

## Шкала мощности на экране

`Control_GetSmoothedPowerPct(ch)` — мощность канала 0–100 %, сглаженная (`CONTROL_POWER_DISPLAY_FILTER_MS`, 300 мс) для гейджа на экране. В ПИД не участвует. Обновляется каждый опрос, в том числе при принудительном выключении — тогда плавно стремится к 0.

## API (`control.h`)

| Функция | Назначение |
|---|---|
| `Control_Init()` | Сбросить внутреннее состояние и выключить оба выхода. Вызывать после `Settings_Load()`, `State_Init()`, `Error_Init()`, `ADS1220_Init()`, `Sleep_Init()` |
| `Control_Poll()` | Один шаг опроса, неблокирующий. Вызывать из главного цикла с периодом `CONTROL_POLL_MS` (10 мс), тем же гейтом, что `ADS1220_Poll()` / `Diag_Poll()` |
| `Control_PresleepSetpoint(ch, setpoint)` | Эффективная уставка PRESLEEP |
| `Control_GetSmoothedPowerPct(ch)` | Сглаженная мощность для индикации, Q16.16 |

## Значения по умолчанию

Kp / Ki / Kd = 500 / 90 / 300 (в единицах `raw`, т.е. 5 / 0.9 / 3.0), подобраны на паяльнике; канал отсоса настраивается отдельно.

## Связь с другими модулями

- Читает `State` (уставка, включён ли канал), `Settings` (Kp/Ki/Kd, PresleepTemp), `Sleep`, `Error` (`Error_IsChannelBlocked()`), `ADS1220` (температура, свежесть отсчёта).
- Пишет `State.current_temp` / `State.heater_active`.
- Замер целостности нагревателя (`Diag`) выполняется в паузах между импульсами ШИМ, когда оба выхода неактивны — см. `Error.md`.

## Реализация

`poll_channel()` — короткая цепочка: `heating_allowed()` (отсчёт АЦП валиден и оценён Diag → нет блокировки → эффективная уставка по режиму сна; иначе `force_off()`) → температура в State → `process_new_sample()` на реально новый отсчёт → `pwm_stage()`. `process_new_sample()`: `update_dTdt()` (фильтр dT/dt), `working_setpoint_for()` (двухстадийная уставка), `pid_step()`. `pid_step()`: `update_integral()` (полоса анти-виндапа, клампинг, `limit_integral_on_overshoot()`) и `pid_output_pct()` (P + I − D в int64, насыщение 0..100 %, округление). Арифметика, порядок вычислений и все пороги прежние; регулятор закреплён golden-тестом в замкнутом контуре с тепловой моделью, который сверяет выход и внутреннее состояние PID на каждом шаге (`make -C tests/control_golden check`; после намеренного изменения алгоритма эталон обновляется `make -C tests/control_golden golden`). Тест включает `control.c` целиком, поэтому статические переменные регулятора (`s_duty_pct`, `s_integral`, `s_dTdt` и др.) должны сохранять имена.

## Публикация температуры

Пока отсчёт АЦП пригоден (валиден, оценён Diag, канал не заблокирован), `poll_channel()` записывает измеренную температуру в State (`State_SetCurrentTemp()`) на каждом опросе — в том числе у выключенного канала (UP+DN) и в `SLEEP`, где нагрев отключён. Так число под иконкой сна остывает вместе с жалом. Раньше запись стояла после проверки эффективной уставки и в этих состояниях не выполнялась: значение замирало на температуре момента засыпания. Нагрев и PID это не затрагивает (трасса регулятора с прежним поведением сверяется режимом `EQUIV=1` golden-теста). При непригодном отсчёте (нет данных, авария, блокировка) температура не публикуется.
