# Error

Интерпретация ошибок из других модулей (EEPROM, диагностика инструментов) в единый источник истины: что показывать на дисплее, что блокировать.

**Чистый интерпретатор** — сам ничего не диагностирует, только принимает готовые факты от других модулей (`Settings_Load()` → `Error_ReportEepromStatus()`; будущий модуль диагностики ADS1220/нагревателя → `Error_SetRtdOpen()`/`Error_SetHeaterOpen()`) и переводит их в состояние, которым пользуются `Fsm` (блокировка фокуса/управления) и `Screen` (цвета/сообщения).

> Не путать с HAL-сгенерированным `Error_Handler()` в `main.c` — это разные, не связанные друг с другом вещи: тот обрабатывает фатальные сбои HAL-инициализации, этот модуль — доменная логика станции.

## EEPROM

`Settings_Load()` возвращает `SettingsLoadStatus_t` (см. `Settings.md`) — результат передаётся в `Error_ReportEepromStatus()` сразу после вызова, один раз при старте:

| Статус | Реакция |
|---|---|
| `SETTINGS_LOAD_OK` | Ничего не делает |
| `SETTINGS_LOAD_INVALID` | Данные были не наши/повреждены, дефолты уже записаны обратно (см. `settings.c`) — транзитное сообщение в инфозоне на `ERROR_EEPROM_TRANSIENT_MS` (5 сек), работу не блокирует |
| `SETTINGS_LOAD_IO_ERROR` | Микросхема не отвечает — "авария EEPROM" на весь сеанс (`Error_IsEepromAlarmActive()` остаётся `true` до перезагрузки; замена микросхемы происходит только при выключенном питании, так что самостоятельно эта авария за время сеанса не пройдёт). Работу тоже не блокирует — просто EEPROM не персистит |

## Инструменты (RTD/нагреватель)

> ⚠️ **Заглушка**: реальный источник данных (диагностика через ADS1220 — обрыв/КЗ RTD, обрыв цепи нагревателя) ещё не написан — плата не распаяна (см. `README.md`, SPI2). `Error_SetRtdOpen()`/`Error_SetHeaterOpen()` — точка входа, которую будущий модуль диагностики будет дёргать каждый цикл опроса; пока их никто не вызывает, оба флага по умолчанию `false` (обрыва нет).

`Solder_Test`/`Desolder_Test`: высокий уровень = исправно.

### Комбинация статусов → `tool_fault_t`

| RTD | Нагреватель | Результат | На экране |
|---|---|---|---|
| открыт | открыт | `TOOL_FAULT_DISCONNECTED` — "инструмент не подключен" | Заголовок и текущая температура красным. Текстового сообщения нет |
| открыт | цел | `TOOL_FAULT_RTD_OPEN` | Красным + сообщение "Обрыв RTD" (на месте целевой температуры) |
| цел | открыт | `TOOL_FAULT_HEATER_OPEN` | Красным + сообщение "Обрыв нагревателя" |
| цел | цел | `TOOL_FAULT_NONE` | Канал работает как обычно |

> Сообщение об обрыве выводится на месте целевой температуры, потому что шрифт `Comic_60_dig`, которым рисуется текущая температура, физически не содержит кириллицы — для текста нужен шрифт `AntiquaB`.

Для **любого** `tool_fault_t != NONE`: нагрев и управление (SET1/2/3, UP/DN) заблокированы (`Error_IsChannelBlocked()`), фокус (TOOLS) на этот канал не передаётся — обе проверки на стороне `Fsm`. Нагрев физически ещё не реализован (Control-слой отложен до платы), `Error_IsChannelBlocked()` заранее готов как точка интеграции для него.

## API (`error.h`)

| Функция | Назначение |
|---|---|
| `Error_Init()` | Инициализация модуля |
| `Error_Poll()` | Обслужить таймер транзитного сообщения EEPROM. Вызывать из главного цикла каждую итерацию (дёшево — сравнение по `HAL_GetTick()`) |

### EEPROM

| Функция | Назначение |
|---|---|
| `Error_ReportEepromStatus(status)` | Вызвать один раз при старте, сразу после `Settings_Load()` |
| `Error_IsEepromAlarmActive()` | `true` — авария EEPROM активна (весь сеанс, до перезагрузки) |
| `Error_GetInfoZoneMessage()` | Текст для инфозоны прямо сейчас, или `NULL`, если показывать нечего. Авария (весь сеанс) имеет приоритет над транзитным сообщением |

### Диагностика инструментов

| Функция | Назначение |
|---|---|
| `Error_SetRtdOpen(ch, open)` / `Error_SetHeaterOpen(ch, open)` | Точки входа для будущего модуля диагностики (пока не вызываются) |
| `Error_GetToolFault(ch)` | Текущая неисправность канала — `tool_fault_t` |
| `Error_IsChannelBlocked(ch)` | `true` — нагрев и управление (SET/UP/DN) заблокированы, фокус не передаётся |
| `Error_IsChannelFaulted(ch)` | `true` — для `Screen`: заголовок и текущая температура канала красным |
| `Error_GetChannelFaultMessage(ch)` | Текст сообщения об обрыве (заменяет целевую температуру на экране), или `NULL` — либо неисправности нет, либо это `TOOL_FAULT_DISCONNECTED` (сообщения не предусмотрено, только цвет) |

## Связь с другими модулями

- `Settings_Load()` — источник статуса EEPROM, см. `Settings.md`.
- `Fsm` использует `Error_IsChannelBlocked()` для блокировки ввода и фокуса — см. `FSM.md`.
- `Screen` использует `Error_IsChannelFaulted()`, `Error_GetChannelFaultMessage()`, `Error_GetInfoZoneMessage()` для отрисовки — см. `Screen.md`.
- Диагностика через ADS1220 (SPI2) — будущий модуль, ещё не написан (плата не распаяна) — см. `README.md`.
