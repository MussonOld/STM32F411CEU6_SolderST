# Error

Интерпретация ошибок из других модулей (EEPROM, диагностика инструментов) в единый источник истины: что показывать на дисплее, что блокировать.

**Чистый интерпретатор** — сам ничего не диагностирует, только принимает готовые факты от других модулей (`Settings_Load()` → `Error_ReportEepromStatus()`; модуль `Diag` → `Error_SetRtdState()`/`Error_SetHeaterOpen()`/`Error_SetAdcFault()`) и переводит их в состояние, которым пользуются `Fsm` (блокировка фокуса/управления) и `Screen` (цвета/сообщения).

> Не путать с HAL-сгенерированным `Error_Handler()` в `main.c` — это разные, не связанные друг с другом вещи: тот обрабатывает фатальные сбои HAL-инициализации, этот модуль — доменная логика станции.

## EEPROM

`Settings_Load()` возвращает `SettingsLoadStatus_t` (см. `Settings.md`) — результат передаётся в `Error_ReportEepromStatus()` сразу после вызова, один раз при старте:

| Статус | Реакция |
|---|---|
| `SETTINGS_LOAD_OK` | Ничего не делает |
| `SETTINGS_LOAD_INVALID` | Данные были не наши/повреждены, дефолты уже записаны обратно (см. `settings.c`) — транзитное сообщение в инфозоне на `ERROR_EEPROM_TRANSIENT_MS` (5 сек), работу не блокирует |
| `SETTINGS_LOAD_IO_ERROR` | Микросхема не отвечает — "авария EEPROM" на весь сеанс (`Error_IsEepromAlarmActive()` остаётся `true` до перезагрузки; замена микросхемы происходит только при выключенном питании, так что самостоятельно эта авария за время сеанса не пройдёт). Работу тоже не блокирует — просто EEPROM не персистит |

## Инструменты (RTD/нагреватель)

Источник данных — модуль `Diag` (`diag.h`): по сопротивлению RTD с ADS1220 определяет его состояние (диапазон 20–80 Ом — норма, вне него `R <= DIAG_RTD_SHORT_MAX_OHM` — КЗ, `R >= DIAG_RTD_OPEN_MIN_OHM` — обрыв; не зависит от калибровки Slope/Bias), плюс страховка по откалиброванной температуре (`t > SETTINGS_TEMP_MAX` — тоже обрыв), по `Solder_Test`/`Desolder_Test` — целостность нагревателя, и каждый цикл опроса передаёт результат в `Error_SetRtdState()`/`Error_SetHeaterOpen()`/`Error_SetAdcFault()`.

`Solder_Test`/`Desolder_Test`: высокий уровень = исправно.

### Комбинация статусов → `tool_fault_t`

| RTD | Нагреватель | Результат | На экране |
|---|---|---|---|
| открыт | открыт | `TOOL_FAULT_DISCONNECTED` — "инструмент не подключен" | Штатное состояние, не авария (не красным): растровый крестик пониженной контрастности на месте текущей температуры, целевая и заголовок как обычно |
| КЗ | любое | `TOOL_FAULT_RTD_SHORT` | Красным + сообщение "КЗ RTD" (на месте текущей температуры) |
| открыт | цел | `TOOL_FAULT_RTD_OPEN` | Красным + сообщение "Обрыв RTD" (на месте текущей температуры) |
| цел | открыт | `TOOL_FAULT_HEATER_OPEN` | Красным + сообщение "Обрыв нагревателя" |
| цел | цел | `TOOL_FAULT_NONE` | Канал работает как обычно |

> Отдельно, высший приоритет среди `tool_fault_t` (см. `error.h`): если АЦП канала не даёт конверсий (`TOOL_FAULT_ADC_FAULT`, см. `Diag_Poll()`/`Error_SetAdcFault()`) — красным + фиксированное сообщение `"ERR ADS1220"` (2 строки), независимо от состояния RTD/нагревателя. Раньше задумывалось как расширяемый код ошибки (E01/E02/...) с расшифровкой в мануале — других причин без диагноза не набралось, упрощено до одного сообщения.

> Сообщение об аварии выводится на месте текущей температуры (в 2 строки), но шрифтом `AntiquaB`: `Comic_60_dig`, которым рисуется сама температура, физически не содержит кириллицы. Целевая температура при этом остаётся числом.

Для **любого** `tool_fault_t != NONE`: нагрев и управление (SET1/2/3, UP/DN) заблокированы (`Error_IsChannelBlocked()`), фокус (TOOLS) на этот канал не передаётся — обе проверки на стороне `Fsm`. Нагрев реализован в `Control`, который обращается к каналу через `Error_IsChannelBlocked()`.

## БП (Pok)

`Pok_Pin` (см. `main.h`/`gpio.c`) — Power OK от блока питания, активный низкий (LOW = питание в норме, HIGH = авария). Читается и репортится в `Error` из `main.c` (10мс-гейт, тот же, что у `Buttons_Poll()`/`Sleep_Poll()`) через `Error_ReportPsuStatus()` — сам `Error` GPIO не читает, остаётся чистым интерпретатором. Без дебаунса — если на реальном железе окажется дребезг, добавить по образцу `sleep.c`. **Временно:** пока БП не обновлён, `Pok` на плате заземлён через 1 кОм, то есть всегда «норма» — авария БП фактически не сработает до нового БП.

В отличие от аварии EEPROM и `tool_fault_t`, авария БП **не защёлкивается** — снимается сама, как только `Pok` снова уходит в LOW (просадка/бросок питания — штатное восстанавливаемое событие, а не то, что требует перезагрузки). До первого опроса в `main.c` модуль фейл-сейф: считает БП неисправным по умолчанию (см. `Error_Init()`), но `main.c` делает разовое чтение сразу после `Error_Init()`, чтобы не мигать сообщением в первые ~10мс, если питание на самом деле в норме.

Авария БП блокирует **оба канала разом** (`Error_IsChannelBlocked()` истинно для любого `ch`, независимо от `tool_fault_t`) и имеет наивысший приоритет в `Error_GetInfoZoneMessage()` — выше аварии EEPROM: "БП не исправен".

## API (`error.h`)

| Функция | Назначение |
|---|---|
| `Error_Init()` | Инициализация модуля |
| `Error_Poll()` | Обслужить таймер транзитного сообщения EEPROM. Вызывать из главного цикла каждую итерацию (дёшево — сравнение по `HAL_GetTick()`) |

### EEPROM

| Функция | Назначение |
|---|---|
| `Error_ReportEepromStatus(status)` | Вызвать один раз при старте, сразу после `Settings_Load()` |
| `Error_IsEepromAlarmActive()` | `true` — авария EEPROM активна (весь сеанс, до перезагрузки) |
| `Error_GetInfoZoneMessage()` | Текст для инфозоны прямо сейчас, или `NULL`, если показывать нечего. Авария (весь сеанс) имеет приоритет над транзитным сообщением |

### Диагностика инструментов

| Функция | Назначение |
|---|---|
| `Error_SetRtdState(ch, state)` / `Error_SetHeaterOpen(ch, open)` / `Error_SetAdcFault(ch, fault)` | Точки входа для `Diag`, вызываются каждый цикл опроса |
| `Error_GetToolFault(ch)` | Текущая неисправность канала — `tool_fault_t` |
| `Error_IsChannelBlocked(ch)` | `true` — нагрев и управление (SET/UP/DN) заблокированы, фокус не передаётся |
| `Error_IsChannelFaulted(ch)` | `true` — для `Screen`: заголовок и текущая температура канала красным |
| `Error_GetChannelFaultMessage(ch)` | Текст сообщения об обрыве (заменяет целевую температуру на экране), или `NULL` — либо неисправности нет, либо это `TOOL_FAULT_DISCONNECTED` (сообщения не предусмотрено, только цвет) |

### БП

| Функция | Назначение |
|---|---|
| `Error_ReportPsuStatus(ok)` | Сообщить текущий статус БП — вызывать КАЖДЫЙ цикл опроса (не одноразово, в отличие от `Error_ReportEepromStatus()`). `ok=true` — `Pok_Pin` в норме (LOW) |
| `Error_IsPsuFaultActive()` | `true` — авария БП активна ПРЯМО СЕЙЧАС (не защёлкивается) |

## Связь с другими модулями

- `Settings_Load()` — источник статуса EEPROM, см. `Settings.md`.
- `Fsm` использует `Error_IsChannelBlocked()` для блокировки ввода и фокуса — см. `FSM.md`.
- `Screen` использует `Error_IsChannelFaulted()`, `Error_GetChannelFaultMessage()`, `Error_GetInfoZoneMessage()` для отрисовки — см. `Screen.md`.
- `Diag` (`diag.h`) — источник данных по инструментам и АЦП (ADS1220 на SPI2, пины `Solder_Test`/`Desolder_Test`). Условие `nPS_ON` для замера нагревателей временно отключено (`DIAG_GATE_REQUIRE_NPS_ON`) — вернуть с новым БП.
