# State

Модель состояния канала паяльной станции — общая точка данных между **Control** (PID) и **UI**-слоями. Ни один из них не знает про другой напрямую — оба общаются только через `State`.

## Правило "кто пишет что"

| Поле | Пишет | Читает |
|---|---|---|
| `current_temp` | Control | UI (только чтение) |
| `heater_active` | Control | UI (только чтение) |
| `in_stand` (датчик "жало в подставке") | Опрос входов (Control или отдельный Input-слой) | UI |
| `setpoint_temp` | Ввод (кнопки), через `Fsm` — см. `FSM.md` | Control, UI |
| `enabled` | Ввод (кнопки), через `Fsm` | Control, UI |

**UI только читает** — ничего не пишет напрямую в `State`. Это правило явно закреплено и используется как прецедент в других модулях (`Settings`, `Screen`) — см. `Settings.md`.

## Синхронизация

Синхронизация — через `volatile` для отдельных полей; для 2-канальной станции этого достаточно (нет строгих требований консистентности между полями одной структуры при чтении из UI).

## API (`state.h`)

| Функция | Назначение |
|---|---|
| `State_Init()` | Инициализировать состояние всех каналов (обнулить) |
| `State_[Get\|Set]CurrentTemp(ch)` | Текущая температура канала, °C (`fixed_t`). Пишет Control |
| `State_[Get\|Set]SetpointTemp(ch)` | Уставка канала, °C (`fixed_t`). Пишет ввод (кнопки) |
| `State_[Set]HeaterActive(ch)` / `State_IsHeaterActive(ch)` | Состояние выхода нагревателя (Solder_On/Desolder_On). Пишет Control |
| `State_[Set]InStand(ch)` / `State_IsInStand(ch)` | Датчик "жало в подставке" (Solder_Test/Desolder_Test) |
| `State_[Set]Enabled(ch)` / `State_IsEnabled(ch)` | Включён ли канал пользователем |

## Общие типы (`App/Common`)

### `channel.h` — идентификатор канала

```c
typedef enum {
    CHANNEL_SOLDER = 0,
    CHANNEL_DESOLDER,
    CHANNEL_COUNT
} channel_id_t;
```

Вынесен в `Common`, а не в `state.h`, чтобы независимые модули (`Settings` и т.п.) могли использовать его, не таща за собой зависимость от `State`.

### `fixed_point.h` — формат чисел с фиксированной точкой

Все температуры в `State` хранятся как `fixed_t` — **Q16.16 фиксированная точка** поверх `int32_t` (атомарный read/write на Cortex-M4, отсюда и выбор такого представления вместо `float` — не нужна блокировка/атомик-секция при чтении из UI, пока пишет Control).

| Макрос | Назначение |
|---|---|
| `FIXED_FROM_INT(i)` | Целое → `fixed_t` |
| `FIXED_TO_INT(f)` | `fixed_t` → целое (отбрасывает дробную часть) |
| `FIXED_FROM_FLOAT(x)` | float → `fixed_t` — **только для констант на этапе компиляции** |
| `FIXED_TO_FLOAT(f)` | `fixed_t` → float — **только для вывода на экран/отладки** |
| `fixed_mul(a, b)` / `fixed_div(a, b)` | Умножение/деление с промежуточным `int64_t`, чтобы не терять точность при сдвиге |

## Связь с другими модулями

- Пишется из `Fsm` (пользовательский ввод) — см. `FSM.md`.
- Читается `Screen` для отрисовки (только чтение) — см. `Screen.md`.
- `Settings` намеренно не знает про `State`/`fixed_t` — хранит те же величины как `uint16_t`, синхронизация — забота `Fsm`, см. `Settings.md`.
- `Control` (PID) — пока не задокументирован отдельным модулем в этом репозитории.
